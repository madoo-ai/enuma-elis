Python code mode: fewer turns, fewer tokens

This repo tests one idea. Let the model write a Python program instead of making a long line of native tool calls. The program calls the same tools, does the routine work, and returns one short result.

The old surface made the model ask for each piece separately. The new surface lets it put the whole check in one program. The latest run already shows the direction: fewer model turns, less context, and less waiting.

Why Python

Python is the shortest path from intent to result. The model already knows the language, so there is no new DSL to teach. A program reads like the work: loops, conditions, and local state fit naturally. When something breaks, one stack trace names the line.

No new DSLThe model already knows Python.
ReadablePrograms are easy to inspect and debug.
ComposableLoops, conditions, and state fit naturally.
Familiar failuresOne stack trace says what broke.

Why code mode

Native tools turn every small step into a model turn. One program can read several files, wait once, compute a check, and return only the value the model needs. Fewer turns mean less context, fewer round trips, and less waiting.

Fewer turnsSeveral tool calls become one model turn.
Less contextThe program returns one short result.
Less waitingIt can wait once instead of polling repeatedly.
Clearer evidenceOne trace reports the whole check.

The tool surface we target

We are not targeting arbitrary Python execution. We target the same tool surface the agent already uses, wrapped in typed Python modules. That keeps the experiment narrow and auditable.

Module What it covers Why it matters
fs Read files, list paths, search text. Most routine turns start here.
shell Run commands, tests, and builds. This is where latency and tokens pile up.
browser Inspect pages, click, fill, and wait. UI checks are the slowest part of the loop.
mutate Apply edits and patches. Keeps changes typed and auditable.

What the old surface looked like

The baseline was a serial shell user, not a parallel tool caller. In one long session, the agent made 1,613 tool calls. Almost every step used exactly one call, and most of those calls were shell. That session spent 84.2% of its cache-read tokens on shell steps and ran for 33.6 hours.

The same session used 2.29M input tokens and 806M cache-read tokens. Thirty runs of 10 or more shell calls held 81% of all shell calls.

What the latest run shows

The latest run moved the other way. It used 226 Python programs and 1,011 child tool calls. Active time was 36.5 minutes, and uncached input was 479k tokens. Only seven outputs were truncated, and the old 25-second browser stall did not appear.

About 4.5× fewer model turns 226 programs did the work of 1,011 native tool calls. An equivalent native-tools run would need roughly 4.5× more model turns.
Several times less token cost Each extra turn carries context again. Code mode returned short results instead of full tool output, which kept uncached input at 479k tokens.

How to read the numbers

These numbers do not come from the same task. The baseline is one long native-tools session. The rerun is one fixed code-mode goal. They show the shape of the problem and the shape of the fix, not a controlled delta.

The direction is still clear. One program replaced about four native tool calls on average. Active time stayed under 37 minutes, and uncached input stayed under 500k tokens.

What this looks like in code

The difference is easiest to see in the two shapes below. Native tools ask for each piece separately. Code mode puts the whole check in one program.

Native tools 
read_file("src/a.py")
read_file("src/b.py")
read_file("src/c.py")
Python code mode 
from agent import fs

paths = ["src/a.py", "src/b.py", "src/c.py"]
out = {p: fs.read(p, limit=80).text for p in paths}
return out
Native tools 
snapshot()
click("Save")
snapshot()
wait_for_text("Saved")
Python code mode 
from agent import browser

page = browser.page()
page.find_one(role="button", name="Save").click()
page.wait_text("Saved")
return {"saved": True}

These snippets are illustrative, not verbatim API calls.

What we are not claiming

We have one clean run, not a controlled native-tools comparison. The numbers show what a fixed code-mode run costs today. They do not yet give the exact multiplier for tokens against native tools.
Baseline source: one long native-tools session recorded in tool-call-stats.md. Latest run: 226 programs, 1,011 child calls, 36.5 active minutes, 479k uncached input tokens.
