Python code mode Compared with native tools
01 — Pitch

Python code mode vs native tools

What we expect to change, what one real run already showed, and what the rerun will measure once it finishes.

02 — The short version

Native tools make every small step a round trip.

Code mode lets the model put the routine work in one program and return one result. That should mean fewer turns, less context, and fewer browser calls.

The current rerun is with the browser and output fixes already in place. We are not comparing against the old version that stalled.

03 — Same work, different shape

What changes in practice

Task Native tools Python code mode
Read three files Three separate model turns. One program, one return.
Wait for a page Repeated polls, each a new call. One wait, then continue.
Check a condition Model sees the full output. Program returns only the value it needs.
Report a failure Each tool error arrives separately. One program reports one trace.

05 — What we expect

The direction we’re looking for

Fewer model turnsOne program can replace several tool calls.
Fewer child callsWaits and reads can batch instead of repeating.
Less uncached inputThe program can return excerpts, not whole files.
Fewer repeated readsState can stay inside one program when it belongs together.
Shorter failure pathsOne program reports the line and the result together.
Clearer evidenceThe model can compute a check and return the value it proved.
These are expectations, not results. The old run pointed at browser polling, hidden truncation, and generated QA diffs as the first places to look.
06 — Why the rerun is worth doing now

The old code mode had three obvious leaks. We fixed them.

Browser waits now check the page state instead of polling. Print output reports what it omitted. Missing paths return a clear error instead of searching the parent directory.

The comparison now uses the corrected version, not the one that stalled. The rerun should show whether the 629 seconds and the 93 hidden truncations disappear.

07 — What it won’t fix

One known cost stays outside code mode.

The QA prompt still carries generated build output. That is issue #10. Code mode won’t shrink that. It also won’t remove the model’s own thinking time.

If the rerun still shows high tokens, that is where to look next.

08 — The ask

One rerun, then compare.

Let the current run finish. Then compare it with native tools on the same goal and the same model.

If code mode wins on turns, tokens, and time, we keep going. If it doesn’t, we stop and say so.
